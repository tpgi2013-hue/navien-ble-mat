# Navien BLE 온수매트 → Home Assistant (ESPHome)

나비엔 **블루투스(BLE) 온수매트**(EQM-560 계열, 광고명 `kdo hotwatermat`)를 ESP32 하나로 Home Assistant에 연결하는 ESPHome 설정입니다.
클라우드·앱 없이 로컬 BLE로 제어하며, 브릿지 1대로 **매트 1~2대**를 붙이고 **BLE 프록시** 역할도 겸합니다.

> 나비엔 공식 제품/앱과 무관한 비공식 프로젝트입니다. 사용에 따른 책임은 사용자에게 있습니다.

## 하드웨어

| 항목 | 사용한 것 |
|---|---|
| 보드 | Seeed XIAO ESP32-C6 (외장 안테나, GPIO3/14로 RF 스위치 전환) |
| 프레임워크 | ESP-IDF, ESPHome 2026.9.x |
| 매트 | 나비엔 BLE 온수매트 싱글 2대 (더블매트 레이아웃도 코드에 포함, 미검증) |

## 테스트된 모델

| 모델 | 구분 | 결과 | 비고 |
|---|---|---|---|
| EQM-560 | 싱글, BLE | ✅ 동작 | 2대 동시 연결 확인 |
| 더블매트 (좌/우 독립) | 더블, BLE | ❔ 미검증 | 코드에 처리 포함. 좌우 반전 등 가능성 있음 |
| WiFi 모델 (navien_smarthome) | WiFi | ❌ 해당 없음 | 통신 방식이 달라 이 프로젝트 대상 아님 |

**내 매트가 호환되는지 확인하는 법**: nRF Connect 등으로 매트를 스캔해서 아래 두 가지를 확인하세요.
1. 광고명이 `kdo hotwatermat` 인지
2. 서비스 `00001c0d-d102-11e1-9b23-2ce2a80000dd` 가 있는지

서비스 UUID가 같으면 같은 프로토콜일 가능성이 높습니다.
다른 모델에서 동작(또는 실패)을 확인했다면 모델명·싱글/더블·결과를 Issue로 알려주세요. 이 표에 추가하겠습니다.

## HA에 생기는 엔티티 (매트 1대당)

| 구분 | 엔티티 | 설명 |
|---|---|---|
| 조작 | `climate` 온수매트 | 켜기/끄기, 설정온도 28~45°C |
| | 운전 모드 (select) | 난방 / 수면 / 빠른난방 |
| | 조작 잠금 (switch) | 컨트롤러 잠금 |
| | 이온케어 (button) | 이온케어 시작 |
| 상태 | 운전상태 (text) | 예: `난방 · 빠른난방 25분`, `오류 E12` |
| | 오류 (binary) | 오류 발생 시 on |
| | 연결 상태 (text) | 정상 / 끊김 / 인증 대기 / 응답 없음 / 거절됨 |
| 설정 | 수면 시간, 조작음 음량 | |
| 관리 | 재등록 (button, 기본 비활성), BLE 사용 (switch) | |

## 설치

1. `components/navien_mat/`를 ESPHome 설정 폴더(`/config/esphome/components/navien_mat/`)에 복사
2. 매트 수에 맞는 YAML을 ESPHome에 추가
   - 매트 1대: `navien-mat-bridge-single.yaml` (프록시 연결 슬롯 3)
   - 매트 2대: `navien-mat-bridge.yaml` (프록시 연결 슬롯 2)
3. `secrets.yaml`에 `secrets.yaml.example`의 항목 추가
4. YAML 맨 위 `substitutions`에 매트 MAC 입력
   - 매트 MAC은 nRF Connect 등으로 `kdo hotwatermat`를 스캔해서 확인 (휴대폰 나비엔 앱은 종료한 상태로)
5. 플래시

### 최초 등록 (매트마다 1회)

1. 플래시 후 `연결 상태`가 `거절됨 (등록 모드 필요)`로 나옴
2. 매트 컨트롤러를 **등록(페어링) 모드**로 전환 (나비엔 앱에 처음 등록할 때와 같은 방법)
3. HA에서 해당 매트의 **재등록** 버튼(기본 비활성 → 엔티티 설정에서 활성화) 누르기
4. `연결 상태` = `정상` 이면 완료. 발급된 deviceID는 ESP에 저장되어 재부팅 후 자동 재연결

## 프로토콜 메모

- 서비스 `00001c0d-d102-11e1-9b23-2ce2a80000dd`, 쓰기/알림 char `...2ce2a80200dd`, 알림 char `...2ce2a80100dd`
- 프레임 20바이트: `[0]=0xB2`, `[19]=Σ[1..18] & 0xFF`
  - `B2 01` 등록/인증 → 응답 `F1 01`(ID 발급) / `F1 02`(인증 완료) / `F1 00`(거절)
  - `B2 00` 상태 (약 1초 주기)
  - `B2 80` 제어
- 운전모드 코드: 1 난방 · 2 예약 · 3 수면 · 4 살균 · 5 오류 · 6 꺼짐 · 7 빠른난방 · 8 이온케어 · 9 사용자 수면
- deviceID는 등록 시 매트가 발급하며, 접속한 브릿지의 BT 주소 기반으로 보임 (같은 브릿지 → 두 매트 모두 같은 ID). 매트는 등록 모드에서만 새 기기를 받음

### 확인된 동작

| 내용 | 근거 |
|---|---|
| 상태 `[5]`가 `00`인 채로 제어하면 온도 변경이 무시될 때가 있음 → 제어 시 `02`로 보정 | 켠 직후 `00`, 수면→난방 후 `02` 비교 로그 |
| 빠른난방은 모드가 아니라 부가기능. 상태 `[15]` = 남은 시간(분, 31부터 감소) | 켜기/끄기 반복 로그 |
| 빠른난방 켜기/끄기: 모드 7 + `[12]=1/0` | 동일 |
| 수면 모드 설정온도 범위 30~33°C | 범위 밖 요청 무시 확인 |
| 꺼진 상태에서 빠른난방 명령은 조작음만 나고 무시됨 | 실기 확인 |

## 연결 슬롯

`esp32_ble.max_connections: 4` = 매트 2 + `bluetooth_proxy.connection_slots: 2` (1대용은 매트 1 + 프록시 3).
광고만 보내는 센서(재실센서 등)는 슬롯을 쓰지 않으므로 프록시 수신에는 영향이 없습니다.
